# Production Read-Modify-Write Audit

Every production mutating function changed by this OpenSpec change must be
entered here before its persistence implementation changes. The audit records
the persisted reads that influence the write, the Ash concurrency safeguard
that owns the invariant, and the behavior or concurrency test that proves it.
Rows remain in this table after implementation so the final review can verify
that no touched invariant silently fell back to application-level
read-modify-write behavior.

| Owner and function | Persisted reads and invariant | Ash safeguard | Verification |
| --- | --- | --- | --- |
| `OfficeGraph.Tenancy.ensure_local_scope/1` | Reads or creates the organization by slug, then its workspace and initiative by parent-scoped slug, plus the default workstream. Exactly one row for each identity must survive concurrent first bootstrap attempts, and all returned records must belong to the same hierarchy. | One transactional generic action declares every touched tenancy resource. Each create uses an Ash upsert action backed by the existing identity and changes no fields on conflict. PostgreSQL 18 `MERGE` can surface a unique violation when two statements concurrently observe the same missing identity, so the boundary retries the complete action once only for the four declared tenancy identity constraints; the failed action has already rolled back before retry. | `OfficeGraph.Foundation.BootstrapTest` proves stable IDs on repeat bootstrap. `OfficeGraph.Integrations.IntakeBootstrapConcurrencyTest` proves two independent first-scope attempts return the same IDs and one row per identity. |
| `OfficeGraph.Content.persist_plain_document/3` | Performs no decision-making persisted read. The invariant is failure atomicity across the document, initial paragraph block, and first revision. | A transactional generic action on `Document` declares the block and revision resources it touches. Any nested Ash create error is returned to the action so Ash rolls back the full action-owned transaction. | `OfficeGraph.WorkGraph.PersistenceTest` proves the document, block, and revision are created as one domain operation and that invalid or unauthorized operation contexts persist none of them. |
| `OfficeGraph.Authorization.ensure_owner_role/2` | Ensures the complete recognized capability catalog, the organization owner role, every owner capability grant, the exact principal/workspace assignment, and policy bundle version 1. Concurrent owner bootstraps must converge without partial grants or duplicate assignments. | One transactional generic action on `Role` declares every authorization resource it touches. Identity-backed Ash upserts preserve existing rows. The boundary retries the complete rolled-back action once only for the declared authorization identity constraints when PostgreSQL 18 `MERGE` loses an initially-missing identity race. | `OfficeGraph.Foundation.BootstrapTest` proves repeat stability and exact grants. `OfficeGraph.Integrations.IntakeBootstrapConcurrencyTest` proves two independent first-owner attempts converge on one assignment and policy bundle. Authorization capability migration suites prove repeat bootstrap repairs missing grants. |
| `OfficeGraph.Authorization.persist_system_role/4` | Ensures the principal/scope-specific system role, requested capability rows, grants, and the nullable workspace assignment. Organization-wide and workspace assignments must remain distinct while repeated and concurrent setup converges. | A transactional generic action on `Role` uses the same identity-backed Ash upserts. `RoleAssignment.unique_assignment` uses `nils_distinct?: false`, so Ash matches nullable workspace identity without partial-index fragments. The same bounded full-action retry handles only declared authorization identity conflicts. | `OfficeGraph.Authorization.SystemRoleTest` proves organization/workspace separation, repeat setup, classified storage failure, and authorization. The owner-bootstrap concurrency suite covers the shared authorization identity race machinery. |
| `OfficeGraph.Identity.ensure_owner/1` | Ensures one principal by exact owner email and one profile by principal. Concurrent local-owner bootstrap must return the same records without leaving a principal without its profile. | A transactional generic action on `Principal` declares `PrincipalProfile` as touched and uses identity-backed create upserts. A single full-action retry is limited to the principal/profile identity constraints after a PostgreSQL 18 `MERGE` conflict has rolled the action back. | `OfficeGraph.Foundation.BootstrapTest` proves stable owner/profile IDs. `OfficeGraph.Integrations.IntakeBootstrapConcurrencyTest` forces two first-owner attempts and proves one principal/profile pair survives. |
| `OfficeGraph.Identity.ensure_session_context/3` | Ensures the one active `local_owner` session for a principal and exact organization/workspace while preserving revoked-session replacement behavior. | The `Session.unique_context` identity owns the partial active-session match; a dedicated Ash upsert action returns the existing active session. A bounded retry handles only its declared unique index race. | `OfficeGraph.Foundation.BootstrapTest` proves repeat session stability and replacement after revocation. The owner-bootstrap race test proves concurrent first session issuance converges. |
| `OfficeGraph.Identity.ensure_system_principal/2` | Ensures one principal per exact email, then verifies the stored kind and active status match the requested system identity. | The principal email identity owns the upsert; no get-then-insert window remains. The same bounded identity-conflict retry re-runs only the single Ash create action. | `OfficeGraph.Authorization.SystemRoleTest` and agent/GitHub integration tests prove repeat system-principal setup and kind/status rejection. |
| `OfficeGraph.Identity.store_oidc_login_transaction/1` | Deletes expired login guards and creates one new database-generated transaction ID in the same operation. Live guards must remain. | A transactional generic action reads expired guards and destroys them through Ash before creating the new guard. Any failure rolls back both pruning and creation. | `OfficeGraph.AuthenticationTest` proves expired guards are pruned while live and newly created guards remain. |
| `OfficeGraph.Identity.consume_oidc_login_transaction/1` | Reads the exact guard, decides whether it is unexpired, and consumes it exactly once. Concurrent callbacks must have one winner. | A transactional generic action performs an Ash `FOR UPDATE` read, destroys the locked row, and returns the validity boolean as a successful action result so expired-row deletion commits. The boundary maps `false` to the public invalid-transaction error after commit. | `OfficeGraph.AuthenticationTest` proves one of two concurrent callbacks succeeds, replay fails, and expired guards fail before provider exchange. |
| `OfficeGraph.Identity.ExternalIdentityReconciliation.reconcile_with_evidence/2` | Reads the provider-subject binding, every link for the normalized verified email, and every principal matching that normalized email before deciding whether to authenticate or persist review. A known subject must remain stable, competing subjects must not both become active, and review outcomes must commit. | One transactional generic action locks normalized-email principals and links plus the exact provider-subject row through Ash `FOR UPDATE` queries in deterministic row order. The normalized match uses Ash string expressions. A provider-subject identity-backed unique conflict retries the complete rolled-back action once. A typed action result represents authentication or committed review without using an error to escape the action transaction. | `OfficeGraph.Identity.HumanAuthenticationTest` proves exact-subject stability, normalized and ambiguous email behavior, conflicting-subject review isolation, lifecycle rejection, and persisted review evidence. The identity concurrency additions cover simultaneous provider-subject reconciliation. |
